### 3. V3PageViewModel最適化

**ファイル**: `src/DocOrganizer.UI/ViewModels/V3PageViewModel.cs`

```csharp
public async Task RegenerateThumbnailAfterRotationAsync()
{
    try
    {
        // 🚀 Phase 1: キャッシュ高速パス（10-30ms）
        if (_page.ThumbnailImage != null)
        {
            SKBitmap? rotatedBitmap = null;
            var leftThumbnail = _thumbnailService.GenerateBitmapSourceFromCache(
                _page.ThumbnailImage, Rotation, out rotatedBitmap);

            if (leftThumbnail != null && rotatedBitmap != null)
            {
                // ✅ PdfPage.SetThumbnailImageが自動的に古いBitmapをDispose
                _page.SetThumbnailImage(rotatedBitmap);
                ThumbnailImage = leftThumbnail;
                return; // ✅ 10-30msで完了
            }
        }

        // 🔄 Phase 2: フォールバック（200-500ms）
        await LoadLeftThumbnailAsync();
        await LoadRightPreviewAsync();
    }
    catch (Exception ex)
    {
        ThumbnailImage = CreateErrorPlaceholder();
    }
}
```

**2フェーズ戦略**:
- Phase 1: キャッシュから高速回転（10-30ms）
- Phase 2: キャッシュ失敗時はファイルから再生成（200-500ms）

## 🔧 技術的詳細

### キャッシュ戦略

**キャッシュの場所**:
- `PdfPage.ThumbnailImage`（SKBitmap）
- Core層で管理

**キャッシュの寿命**:
- ページ削除時: PdfPage.Dispose()で自動削除
- サムネイル更新時: SetThumbnailImage()で古いものをDispose

**メモリ管理**:
- SetThumbnailImage()が自動的に古いBitmapをDispose
- メモリリークなし

---

### エラーハンドリング

**シナリオ1: メモリ不足**
- 500MB超のBitmap回転は拒否
- 自動的にフォールバック（ファイルから再生成）

**シナリオ2: キャッシュ破損**
- RotateCachedBitmapがnullを返す
- 自動的にフォールバック

**シナリオ3: 変換失敗**
- BitmapSource変換失敗時
- rotatedBitmapをDispose
- 自動的にフォールバック

---

## ⚠️ 既知の制限

### 1. 初回回転は最適化なし
**理由**: キャッシュ構築が必要
**影響**: 初回のみ200-500ms（2回目以降は10-30ms）

### 2. 右側プレビューは別処理
**理由**: 既にTransformedBitmap使用
**影響**: なし（既に最適化済み）

### 3. PDF出力はキャッシュ不使用
**理由**: SourceImagePathから高品質出力
**影響**: なし（現在の方式が正しい）
