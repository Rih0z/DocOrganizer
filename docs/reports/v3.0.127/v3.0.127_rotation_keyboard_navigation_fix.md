## 📋 修正概要

### 問題
回転処理後に↓↑キーを押すと、選択中のページが強制的に1枚目に移動してしまい、連続回転作業が困難になっていました。

### 解決策
単独の↓↑キーをページ選択移動コマンド（`NextPageCommand`/`PreviousPageCommand`）にバインドし、ListBoxのデフォルトキーボードナビゲーションを無効化しました。

---

## 🔍 バグ詳細

### 症状
```
例: 10枚の画像の5枚目を選択して回転処理を実行
    ↓キー押下 → 期待: 6枚目が選択される
             → 実際: 1枚目に強制移動
```

### 影響
- **ユーザーワークフロー**: 連続回転作業が困難
- **頻度**: 回転処理後に毎回発生
- **重要度**: 高

---

## 🎯 根本原因

### 原因1: TwoWayバインディングとイベント制御の不整合
- `RefreshPageListWithSelection`メソッドで`SelectionChangedイベント`のみ無効化
- `TwoWayバインディング`は有効なまま
- `SyncSelectionFromViewModel`内の`SelectedItems.Clear()`が副作用を発生

### 原因2: Dispatcher遅延によるタイミング問題
- イベント再有効化が`DispatcherPriority.Loaded`で遅延実行
- ユーザーが↓キーを押すタイミングによっては内部状態が不安定

### 原因3: ListBoxデフォルトナビゲーションの動作
- 単独の↓↑キーは`ListBoxのデフォルトキーボードナビゲーション`が処理
- `SelectedItems`コレクションが不整合な場合、デフォルト動作として**index 0を選択**
- これがWPFのListBoxの標準動作

### 技術的詳細
以前は単独の↓↑キーは何のコマンドにもバインドされておらず、ListBoxのデフォルトキーボードナビゲーションが動作していました：

```xaml
<!-- 修正前: 単独↓↑キーはバインドなし -->
<KeyBinding Key="PageUp" Command="{Binding PageOperation.PreviousPageCommand}"/>
<KeyBinding Key="PageDown" Command="{Binding PageOperation.NextPageCommand}"/>
```

### 実装方針
バグ分析で提案された**案1: キーボードショートカットの追加**を採用しました。

**選択理由**:
1. **最も安全で確実** - 既存コードへの影響が最小
2. **実装が簡単** - XAMLに2行追加するだけ
3. **テストが容易** - 動作確認が明確
4. **既存メソッドの活用** - NextPage/PreviousPageメソッドは既に実装済み
5. **一貫性の向上** - PageUp/PageDownと同様の処理フロー

## 💡 技術的な学び

### WPFのListBoxキーボードナビゲーション
- ListBoxはデフォルトで↓↑キーのキーボードナビゲーションを実装
- `SelectedItems`コレクションの状態が不整合な場合、index 0を選択する動作がある
- カスタムコマンドをバインドすることでデフォルト動作を無効化可能

### TwoWayバインディングとイベント制御
- イベントを無効化してもTwoWayバインディングは有効なまま
- `SelectedItems.Clear()`などの操作は、TwoWayバインディング経由で副作用を発生させる可能性
- Dispatcher遅延実行とユーザー操作のタイミング競合に注意

### 修正アプローチの選択
- 複雑な内部動作の修正よりも、外部インターフェース（キーボードショートカット）の調整が安全
- 既存の実装済みメソッドを活用することで、リスクとコストを最小化
