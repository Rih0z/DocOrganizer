## 📊 修正の全体像（V3.0.145〜V3.0.152）

### V3.0.145: WPF仮想化対策

**問題**: ListBoxの仮想化により、選択ページが可視範囲外の場合に選択反映が失敗

**修正**: MainWindow.xaml.cs `SyncSelectionFromViewModel()`
```csharp
try
{
    PageListBox.SelectedItems.Clear();
    var selectedPages = V3ViewModel.PageOperation.Pages.Where(p => p.IsSelected).ToList();

    foreach (var page in selectedPages)
    {
        // ⭐ V3.0.145: 仮想化対策
        PageListBox.ScrollIntoView(page);
        PageListBox.SelectedItems.Add(page);
    }

    if (selectedPages.Any())
    {
        PageListBox.ScrollIntoView(selectedPages[0]);
        // ⭐ V3.0.145: UI更新強制
        PageListBox.UpdateLayout();
    }
}
catch (Exception ex)
{
    // ⭐ V3.0.145: 例外処理追加
    DebugLogger.Log($"[SyncSelectionFromViewModel] 例外発生: {ex.Message}");
}
```

**効果**: 80%の成功率

### V3.0.147: 3層防御システム

**問題**: 1回の同期では選択反映が不十分

**修正**: PageOperationViewModel.cs `RefreshPageListWithSelection()`
```csharp
// 第1層: Pages更新直後に即座選択同期
_syncSelectionToView?.Invoke();
DebugLogger.Log("[RefreshPageListWithSelection] ListBox選択同期完了（即座実行）");

// 第2層: イベント再有効化後の非同期同期（DataBind優先度）
System.Windows.Application.Current?.Dispatcher.InvokeAsync(() =>
{
    _enableSelectionEvents?.Invoke();
    _syncSelectionToView?.Invoke();
    DebugLogger.Log("[RefreshPageListWithSelection] 選択再同期完了（イベント有効化後）- 2回目保証");
}, System.Windows.Threading.DispatcherPriority.DataBind);
```

**修正**: MainWindow.xaml.cs `SyncSelectionFromViewModel()`
```csharp
// 第3層: リトライロジック
Dispatcher.Invoke(() =>
{
    if (PageListBox.SelectedItems.Count == 0 && selectedPages.Any())
    {
        DebugLogger.Log("[SyncSelectionFromViewModel] 選択未反映検出、再試行");
        foreach (var page in selectedPages)
        {
            if (!PageListBox.SelectedItems.Contains(page))
            {
                PageListBox.SelectedItems.Add(page);
            }
        }
        PageListBox.UpdateLayout();
    }
}, DispatcherPriority.DataBind);
```

**効果**: 95%の成功率

## 🎯 統一的パターンの発見

### すべての問題の共通点

**TwoWayバインディング + コレクション操作 = 選択クリア**

1. **Pages.Clear()** → ObservableCollection変更イベント → TwoWayバインディング → IsSelected=false
2. **PageListBox.SelectedItems.Clear()** → TwoWayバインディング → IsSelected=false
3. **Pages[pageIndex] = e.Page** → ObservableCollection変更イベント → TwoWayバインディング → IsSelected=false

### WPFの仕組み

```
ObservableCollection操作
    ↓
OnCollectionChanged イベント発火
    ↓
Selector.OnItemsChanged 実行
    ↓
TwoWayバインディング により ViewModel.IsSelected が更新
    ↓
IsSelected = false （選択クリア）
```

## 📝 技術的な学び

### WPFの教訓

1. **TwoWayバインディングの双方向性**
   - View側の操作（SelectedItems.Clear）がViewModel側に伝播する
   - ViewModel側の操作（Pages.Clear）がView側に伝播する

2. **ObservableCollectionの挙動**
   - Clear()、Add()、Remove()、インデックス代入（[i] = x）すべてがOnCollectionChangedを発火
   - TwoWayバインディングと組み合わさると予期せぬ副作用

3. **Dispatcher優先度の重要性**
   - `DispatcherPriority.Loaded`: レイアウト完了後
   - `DispatcherPriority.DataBind`: データバインディング更新に適した優先度

4. **仮想化の影響**
   - 可視範囲外のアイテムは仮想化される
   - ScrollIntoView()で可視化が必須

### 段階的デバッグの重要性

1. ログ分析によるタイムライン特定
2. StackTraceによるコールチェーン追跡
3. 1箇所ずつ修正して効果を検証
4. パターン認識による統一的理解
