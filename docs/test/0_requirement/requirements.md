# DocOrganizer テストフレームワーク実装 - 要件定義書（改訂版）

## 概要

V3.0.153でデバッグフラグの完全統一（23箇所修正）を達成したDocOrganizerに対し、包括的なテストフレームワークを構築する。現在のテストカバレッジ0%を80%以上に向上させ、V3.0.153の核心である「デバッグフラグ統一の検証」と「V3.0.145-152の回帰防止」、「核心機能の品質保証」を実現する。

## 前フェーズからの引き継ぎ事項

なし（初回フェーズ - 改訂版）

**プロジェクト背景**:
- **V3.0.153**: 23箇所のデバッグコードをフラグでガード化完了
  - V3DragDropInfo.cs: 17箇所（CalculateInsertIndex: 12, FindParentListBox: 5）
  - PdfPerformanceMonitor.cs: 1箇所（GenerateMonthlyReportAsync）
  - SimpleDebugTest.cs: 2箇所（クラス全体）
  - App.xaml.cs: 3箇所（エラーハンドラ）
- **V3.0.145-152**: 回転後選択維持バグ修正（8バージョン、3箇所の根本修正）
- testsフォルダが削除されており、ユニットテストが存在しない
- 静的解析とコンパイル検証のみで品質保証している（テストカバレッジ50%）

## 本フェーズの成果物

**目的**: DocOrganizerの品質保証体制を強化し、V3.0.153の核心である「デバッグフラグ統一」の検証と、V3.0.145-152で修正した「回転後選択維持」の回帰防止、および核心機能の品質保証を実現する。

2. **V3.0.145-152の回帰防止**: 回転後選択維持の3箇所修正が破壊されないことを保証
3. **核心機能の品質保証**: PDF編集、回転、Undo/Redoの正常動作を保証
4. **テストカバレッジ80%以上**: CI/CD統合による継続的品質保証

#### 1.2 副次的目的

1. **開発者体験の向上**: テストにより安全なリファクタリングが可能に
2. **ドキュメント化**: テストコードが仕様書として機能

### 11. 技術スタック選定（仮決定）

**テストフレームワーク**: **xUnit**（仮決定）
- **理由**:
  - .NET標準、Visual Studio完全統合
  - 並列実行サポート（テスト時間短縮）
  - 豊富なアサーションライブラリ（FluentAssertions）
  - BenchmarkDotNetとの統合が容易
- **代替**: MSTest（シンプル）、NUnit（レガシー互換）
- **最終決定**: 基本設計フェーズで比較表を作成して決定

| 技術要素 | 選定技術 | 選定理由 |

### 用語集

| 用語 | 定義 |
|------|------|
| **トレーサビリティID** | 要件からテストケースまで追跡可能にする一意識別子（例: V153-001） |
| **回帰テスト** | 既存機能が新しい変更により破壊されないことを検証するテスト |
| **Phase** | 実装の優先度に基づく段階（Phase 1: 必須、Phase 2: 推奨、Phase 3: オプション） |
| **コンパイル時テスト** | ビルド済みアセンブリを解析し、期待される構造になっているか検証するテスト |
| **静的解析テスト** | ソースコードを実行せずに解析し、パターンマッチングで問題を検出するテスト |
| **Flaky Test** | 同じコードで実行のたびに結果が変わる不安定なテスト |
| **IL (Intermediate Language)** | .NETの中間言語。C#コードがコンパイルされた後の形式 |
| **ベースライン** | パフォーマンステストにおける比較基準となる測定値 |
| **Git LFS** | Git Large File Storage。大容量ファイルを効率的に管理する仕組み |
